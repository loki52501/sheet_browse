## Rules

- **One PR per task (D-91).** Each task gets its own branch `swarm/<area>-T<nn>` (follow-ups: `swarm/core-T05d`, `swarm/sheet-T10b`). For parallel tasks use one worktree each: `git worktree add F:/sb-swarm/wt/<area>-T<nn> -b swarm/<area>-T<nn> main` (keep `SB_AREA` set; it is in your environment). Start every task branch from current `main`.
- **Real PRs (D-86).** When a task is ready: `git push -u origin swarm/<area>-T<nn>`, then `gh pr create --base main --head swarm/<area>-T<nn> --title "<area>: T-<nn> <what>" --body "<review and accept report paths, the one command that proves it>"`. Never push main. Never force-push. The supreme merges.
- **Merge rule (D-87).** A PR merges when its review has no Blocking items and `cargo test --workspace` passes. A red acceptance item does not block: list it in the PR body and file it as a follow-up task (`T-<nn>b`) in agent-memory/tasks.yaml on your branch. Hard rules still block: a vault value that can leak, a captcha path that does not stop, a side effect outside the gate.
- **Two review rounds, then ship (D-89).** Round 1: reviewer + tester. Round 2: fixes. Then open the PR with whatever is left filed as follow-ups. Run the `pr-ready` skill (.claude/skills/pr-ready) before round 1 and before the PR.
- **Interface freeze (D-90).** No changes to agent-memory/interfaces.yaml until T-17. If a trait is wrong, work around it inside your crate and file the proposal under `interface_changes`; the answer is "deferred to wave 4". Do not wait for it.
- **No holds (D-88).** Nothing you do waits on another area's should-fix. If you truly need code that is not on main yet, merge that area's branch into your task branch locally and say so in the PR body.
- Temp stays on F: (`TMP`/`TEMP`/`TMPDIR` are set for you). Handoffs as before; one per task in agent-memory/handoffs/.
