## Round 1 Blocking, closed

1. **settled true while a request is in flight (cap over 3 s): closed.** Every exit of `net_settle` (settle.rs:268, 286, 315, 324, 329) goes through `honest()` (settle.rs:216), which sets `settled = false` when any tracked request of the tab announced after `pending_since` is in flight, whatever its age. `settle_tab` uses `pending_since: 0` (settle.rs:367), `w(d)` too (actionable.rs:682), the act window the step's mark (act.rs:726). The remaining `settle_tab` exits (timeout, dialog, `Deadline`) already return unsettled. Tests: `a_w_step_over_3_s_is_unsettled_while_its_request_is_in_flight` and `settle_over_3_s_is_unsettled_while_an_aged_request_is_in_flight` (lib.rs) assert `Some(false)` / `settled: false` and the 2.9 to 3.5 s timing. The coder reports both went red with the check off.
2. **Act window past 3 s: closed.** A busy first wait ends at `deadline - INDEX_ROOM` (settle.rs:259), its call is index-only (cap 0), every act-window call gets `min(per_call, left - REPLY_MARGIN)` and `call_deadline = min(now + cap + grace, deadline)` (settle.rs:289). The re-run of `post_step` after a document change reuses `t0` (act.rs:802), the navigation wait and the opened-tab wait use `nav_cap`, and `tab_title(t, nav_cap)` caps the title read (act.rs:920). A call past its deadline fails at once and gives `Some(false)`. The lib test now asserts `cap: 0` and total from the input <= 3040 ms. accept_t22.rs:728 asserts <= 3040 ms from the XHR start.
3. **`role` not scrubbed: closed.** `scrub_rows` (merge.rs) destructures `IndexRow`, `Flags` and `State` with exhaustive patterns (no `..`), so a new string field will not compile until it is handled. It scrubs and then caps role, name, nearby, heading, form, landmark, input_type, autocomplete, the text value and options. The other fields are ids, bools, numbers or `bbox`. Tests: `every_row_string_is_scrubbed_and_capped` (mock) and `index_rows_never_carry_a_vault_value` (accept_t22.rs:735, real browser, canary written into the page at run time, checks both serde and Debug forms, `role` included).

## Should-fix

1. **D-625 makes long-poll pages unsettled forever** (settle.rs:133 `pending`, settle.rs:216 `honest`). `pending_since: 0` counts every tracked request of the tab with no age limit. A page that holds a long-poll XHR/fetch open all the time (Gmail's channel, chat apps; not filtered by `NET_IGNORED`) now gets `settled: false` from every `settle()` and `w(d)`. An `inflight` entry that never gets `loadingFinished`/`loadingFailed` (keepalive fetch after navigation, a frame that detaches while its session lives on) has the same effect until the session goes or `NET_CAP` evicts it. Before this round such an entry aged out after 3 s and was harmless. This follows the letter of B-4 #8, but docs/07 drives mail through Gmail, and a model that keeps seeing `settled: false` spends extra turns (priority: efficiency). Suggestion: add a long-poll fixture and a blocker for supreme. Options: drop non-document requests of a frame when that frame commits or detaches, or exempt requests that were already in flight more than N seconds before the settle began.
2. **D-626 says the walk and its reply end by commit + 3 s, but nothing in Rust enforces that** (lib.rs:657, lib.rs:673). Only the in-page settle gets `left - REPLY_MARGIN`. `based_ctx` is called with `deadline = now + OPEN_CAP` (30 s), so a slow based walk on a heavy DOM returns after commit + 3 s. Rows 03f to 03j pass on light pages (max 3.015 s). Either give the walk call a hard deadline of `settle_end` (with whatever fallback D-73 allows) or narrow D-626's wording to "the in-page settle".
3. **A hidden-page window can still claim NoVisibleChange** (act.rs:71 POST_FN, act.rs:435). With D-627 a hidden page skips the in-page settle and returns its index at once, so the window is effectively 0 ms. The `quiet` test does not look at `settled`. After a target=_blank click the `OpenedTab` consequence blocks the claim, but a tab hidden for another reason (window minimized during the step, an opener mapping that is missing) diffs an index read before any effect and can report NoVisibleChange. That invites a retry of the step. Cheap fix: have POST_FN return `hidden: true` and drop the claim when it is set.
