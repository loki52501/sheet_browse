## Blocking

- injected.js:936..:967 `twinOfHiddenPw` (hard rule 5, D-444 (1) conformance): the
  sibling-wrapper branch only takes the input's immediate parent as the wrapper. D-444 (1)
  says "the twin and the hidden sensitive field each sit alone in sibling wrappers of one
  parent". Z7 (`x-in > div.c > input`), Z7v (`div.base > label + div.control > input`) and Z7i
  meet that wording at depth 2, and Z5m (pw in a span, twin direct, in one label) is the
  mixed-depth form. All four report `settled: true` after click Show, then put the password in
  index/text/state at every read for the life of the page (runs/reviewer-14/out/chromium-r14.txt).
  This is the round 8 standard: a component-wrapped `v-show` / `[hidden]` twin pair is the
  normal way to write Y7 in Vue or Angular with a shared input component.
  - Prototype (runs/reviewer-14/fix, fix.diff): climb from el while the ancestor's only value
    field is el (cap 6 levels). At each level, a sibling subtree whose only value field is a
    hidden sensitive one masks el. onlyField is memoized in S.hid.o for the index() call.
    Z5m, Z7, Z7v and Z7i read 0, and Y6, Y7, Y7w and Y7i stay 0. `node --test injected/test/`
    is 113/113, and the cost test passes 3 of 3. Without the memo, the cost test fails
    (index 160 ms).
  - Tests needed: Z7v and Z5m shapes in d444-twins.html, plus a depth-2 jsdom case.

## Should fix

- Z6 (settle, B-4 #8, injected.js:2352): settle resolves in the transition's `finished`
  reaction, before the transitionend handler that commits the exit (`display:none`, removal).
  A read in the same evaluate as settle sees the overlap. The driver's I-9 settle is a
  separate call, and the next evaluate reads 0, so this is Should fix. The prototype
  re-checks one task later, which closes Z6 and gives 113/113. That `setTimeout(0)` is a yield,
  not a fixed sleep, but it still needs the rule 6 comment. Waiting on transitionend /
  animationend with the cap also works.
- Z3, Z4, Z4v (a stacked twin hidden by opacity 0, off-screen or sr-only clip): `displayed()`
  is true, so D-444 (1) does not apply. This is Should fix rather than Blocking, because the
  framework hide idioms (display, `hidden`, visibility, `.hidden`) are all covered, and a twin
  password hidden only by opacity or position is atypical. Supreme may widen "not displayed"
  for sensitive fields to include opacity 0, zero-size clip and off-viewport. That widening
  only affects the hidden-password test, not readers.
- Accepted-cost reporting (probe-r14-cost.js): D-444 (1) masks fields that already hold a
  value, and with no evidence they report `empty`. c1 (a flat form plus a display:none trick
  password) and c4 (one div per field plus a hidden password wrapper) read a pre-filled email
  and textarea as `empty`. That is a false statement, not just a coarse one, and a planner
  will retype the field. tester-9 note 5 says the same. T-19b.
- Tests: the jsdom D-444 (1) case covers the light-DOM element parent only. Neither the
