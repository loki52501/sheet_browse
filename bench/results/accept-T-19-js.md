Notes for the next agent

1. media.js shape before the base (low, contract wording). `__sbMedia.frame(id, t)` returns `{t:null, why:"no base"}`, and `frames(id, [0.1, 0.2])` returns one entry `[{t:null, why:"no base"}]` for two times. Every whole-call refusal does this (gone, challenge, DRM too), and media.test.js pins it. D-423 says both "one entry per time, in order" and "before the first based walk every call returns {why: no base}", and this shape is literally neither. I-11 promises a bare `{why}` only for list() and cues(), so this is not counted as a fail. Proposed default: the interface notes say that a single `t:null` entry is a whole-call refusal, and sb-media checks for it before mapping entries to times.
2. FLAG for the spec owner (D-429 (2) against D-405 (5)). On a page whose only widget is an invisible reCAPTCHA v3 badge, or a v3-bound `<button class="g-recaptcha" data-sitekey>`, an "Are you human?" heading becomes CHALLENGE. Probe `runs/accept-T-19-js-r2/probe-v3-quiz.js`: quiz alone false; quiz + v3 badge true; quiz + v3-bound button true. D-429's wording allows this, since a widget and a response field are present. But D-405 (5) and D-424 mean v3 never causes a stop. So a quiz or marketing heading on a v3 site would hand back to the user for nothing. Proposed default: the passive v3 markers (badge, invisible size, data-sitekey on a button) do not count as challenge context.
3. Not covered, by design (js-coder-3 not_done 4 and 5): a rebuild that inserts the new field in a later task or into an unrelated parent; open shadow roots the observer does not see; fields built detached. The outgoing vault scrub stays the backstop.
4. Uncommitted files from another agent were in the tree during this run (`crates/sb-act/tests/accept_t19_round4.rs`, `common/mod.rs`, `accept_t19_round5.rs`). They were not touched or committed. They do not affect `--test wire_from_injected`.
