Notes for the next agent

1. (FLAG, item 3c) settle() on a blank document always runs the full 3 s cap: about:blank (3013..3016 ms) and a loaded page with an empty body (3004..3012 ms). D-416 condition (d) waits for content, which is what makes the SPA case hold. But a new tab, an about:blank popup, or a page that is legitimately empty pays 3 s per settle, and CLAUDE.md ranks latency second. Possible defaults, for a spec owner: sb-driver skips settle for about:blank, or (d) gives up after readyState complete plus one quiet window with no pending timers or requests. Nothing was changed here.
2. The uncommitted edits in this worktree (`injected/injected.js` +334, `injected/media.js` +132, `injected/test/helpers.js`, `injected/test/jsdom.test.js`; mtimes 03:38..03:47) break `injected/test/media.test.js`: `{"why":"no base"}`, `undefined !== 2`, `1 !== 27`, `'no base'` (runs/accept-T-19-js/wt-media-now.tap). Either media.test.js needs a walk({base}) first, or __sbMedia should not require a base. This verdict does not cover those edits; they need their own acceptance run.
3. `node --test injected/test/` does not load the new `accept-t19.test.js`, because injected/test/index.js requires only the three original suites, and testers may not edit existing files. The js-coder should add `require("./accept-t19.test.js");` to index.js and the file to the `npm test` script.
4. Not covered in page, by design: Rust retry/backoff and the 5 s act cap, settle's network-idle half, consequence capture and registry (acceptance 3 and 4), and find() ranking (acceptance 6 Rust side). These belong to sb-driver and sb-sheet.
