## Failing rows: what is missing, owner

- **3c (D-512, W-2): `plain_source` is quadratic. Blocking.** Owner: servers rust-coder (srv-web).
  - Cause: `plain_bracket` searches to the end of the line (html.rs:348) for every `<name` that is not a known element.
  - Fix: bound the `>` search to `PLAIN_BRACKET_MAX` bytes from the `<`, stopping at a newline. Also put a deadline on the `spawn_blocking` walk (fetch.rs:296), so no body can hold a call past the 15 s budget.
  - Proving test: `accept_t12b::text_plain_hostile_angle_runs_finish_in_time`.
- **4b (B-590, D-509): api sends a name that resolves private through the system proxy.** Owner: servers rust-coder (srv-web); supreme to amend D-509 if the scope changes.
  - Cause: `Clients::api_for` needs the same pre-check `page_for` does. When `proxied(url)` holds and the host is a name, it should resolve the name with `PublicOnly::public` and use `api_local`/`api_vault_local` (no proxy) when every answer is private or there is no answer. It may refuse or connect direct from there, as it does without a proxy.
  - Proving test: `accept_t12b_proxy::private_and_loopback_targets_never_use_the_proxy_public_ones_do`, which needs this machine's name to resolve only privately and checks that first.
- **7b (D-513): an empty, whitespace or `#` link and an iCal event without `URL` get the feed's own URL.** Owner: servers rust-coder (srv-web).
  - Fix: `link_url` should return `None` for an empty or fragment-only href before `base.join` (review-T-12b should-fix 1).
  - Proving test: `accept_t12b::feed_items_without_a_link_do_not_get_the_feed_url`.
- **3b and 6b (rule 5): entity-spelled markup reaches the model as tags.** Same cause in text/plain fetch, search snippets and titles, and feed summaries. Owner: servers rust-coder for the code; the servers sub-orchestrator or supreme for the ruling.
  - Cause: the walk and `fragment_text` decode `&lt;`/`&#60;` after dropping tags, so `&lt;script&gt;` comes out as `<script>`. The text/html walk does the same, so this predates T-12b, but T-12b's own invariants (`!has_tag` on the walk text, `!t.contains('<')` on feed and search output) do not hold for such input.
  - Decision needed: either escape `<` in decoded text the way `plain_source` does (`&lt;`), or record a decision that decoded entity text is page text and not markup under rule 5, and drop rows 3b and 6b.
  - Proving tests: `accept_t12b::text_plain_entity_spelled_tags_are_not_shown_as_tags` and `accept_t12b::search_and_feed_entity_spelled_markup_is_not_shown_as_tags`.
- **Test gap (not a row): the D-510 escape tests contain no real JSON escape.** `t12b::api_never_shows_markup_hidden_in_json_escapes` and `api::tests::escaped_markup_in_plain_text_or_a_json_string_document_is_not_shown` hold plain `<`, and they pass with D-510's decoded check removed. accept_t12b's `/u*` cases cover the escape case. Owner: servers rust-coder, to build the escape from `char::from(92u8)` as accept_t12b does.
